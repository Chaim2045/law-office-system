# Rubric — PR-P1: master-detail rail polish (hours ratio + status dot + subtle selection)

**Track:** Admin master-detail **design polish** (frontend-ui-expert change-map, 2026-08-03) — bringing the live client-management card up to the approved master-detail mockup (artifact 227d1403). PR-P1 of the Haim-approved 4-PR sequence (P1 rail → P2 detail hero/progress/title → P3 stages → P4 client pills). Haim also locked: **orange for high-utilization, red reserved for overdraft/blocked** (applies to P2; P1 uses orange for the rail attention dot).
**Scope:** **frontend-only.** `UnifiedServiceCard.buildRailRow` (+ a `railRatioHtml` helper) + the `.cm-rail-*` rules in `clients-modals.css` + a feature-local tint token + `?v=` bump on `clients.html` (both `clients-modals.css` and `UnifiedServiceCard.js`) + the `manage-cutover.test.ts` rail coverage (2 retargeted + 4 new). `buildManageDetail`, `ServiceCardModel`, the injectors, rules, callables — **UNTOUCHED**.
**Type:** display + render-order only. Rail rows carry NO `.management-*` classes → no injector matches them (DA-3), so this cannot affect the overdraft / add-package injectors, counts, filters, or aggregates.

## MUST (all required for PASS)

- **M1 — rail hours ratio.** Every service row that has hours shows a `.cm-rail-row-ratio` "used/total" (1-decimal, tabular figures) pushed to the row's inline-end (left in RTL, opposite the name) via `margin-inline-start:auto`. Source: the service-level rollup (`card.totalHours`/`card.hoursUsed`); when that total is 0 but the card carries stages, it falls back to the **sum over stages** (legal procedures keep hours on stages). A priceless service (total 0, no stages) shows **no** ratio. Type-agnostic (no inline service-type classification). Overdraft is shown truthfully (e.g. `58.3/20.0`).
- **M2 — clean status dot (green/orange), type icon dropped.** Every service row emits exactly one `.cm-rail-row-status` dot: `--ok` (green `var(--green)`) when healthy, `--attention` (orange `var(--orange)`) when `railNeedsAttention` (blocked OR unresolved negative remainder). The type emoji icon is **removed** from service rows (the detail panel's type badge carries type — mockup parity); the "כללי" general row **keeps** its `.cm-rail-row-icon`. NOT color-only (WCAG): an attention row still sets the row `title="דורש טיפול"` + a visually-hidden `.cm-rail-row-sr` label — both PRESERVED.
- **M3 — subtle selection.** `.cm-rail-row--active` = a faint surface (`--cm-active-surface`) + **dark** text (`var(--gray-900)`) + a thin active-bar via `::before` on the logical `inset-inline-start` edge (right in RTL) — replacing the old heavy `--blue-light` solid fill. No layout shift (pseudo-element). Applies to BOTH the general and service rows (shared class). Contrast ≥ WCAG AA.
- **M4 — injector contract untouched.** `buildRailRow` still emits NO `.management-*` classes; `buildManageDetail` (the `.management-service-card[data-service-id]`, `.management-stage-name`, `.management-stage-info`, the 5 `data-service-action` buttons) is byte-unchanged. The overdraft/add-package injectors are unaffected.
- **M5 — no data / count / callable change.** The ratio + dots are pure display derived from the existing `card` view-model. No callable, aggregate, filter, count, sort, or status semantics is touched. `railNeedsAttention` logic is unchanged (only the dot's color-class + always-emit is new).
- **M6 — tokens + accessibility.** Tokens only — the tint is a **feature-local** `--cm-active-surface` declared on `.cm-split` in the versioned `clients-modals.css` (NOT `design-system.css`, which is loaded unversioned by `clients.html` → a stale-cache risk); dots/ratio use existing `--green`/`--orange`/`--gray-500`/`--blue`/`--text-sm`. Reduced-motion safe (no animation on the dot/ratio/bar). RTL via logical properties (`margin-inline-start`, `inset-inline-start`). `:focus-visible` on rows preserved.
- **M7 — gates.** Full admin-panel vitest green (449, was 445 + 4 new − 0 net removed, 2 retargeted); ESLint 0 errors (0 warnings on the touched file — the `railRatioHtml` helper is type-agnostic, so no `no-restricted-syntax` service-type flag); stylelint 0; `?v=` bumped on `clients.html` for both `clients-modals.css` and `UnifiedServiceCard.js`.
