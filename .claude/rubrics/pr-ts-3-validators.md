# Rubric — PR-TS-3: migrate `functions/shared/validators.js` → TypeScript (גל-3ה, module 3 of the safe tier)

**Scope:** Third JS→TS migration, applying the **A′ template** proven in TS-1 (#496 logger) + TS-2 (#498 claim-writer). Migrates `validators.js` — 5 input-validation utilities (`sanitizeString`, `isValidIsraeliPhone`, `isValidEmail`, `isValidIsraeliId`, `getDescriptionLimit`). 6 real consumers, ~25 `jest.mock` sites + 2 direct-behavior tests. **1:1 behavior port, ZERO logic change.**

## Why TS-3 differs from TS-1/TS-2
- **No prior `.d.ts`** (logger + claim-writer both had a hand-written one) → A′ **generates** the first declaration; no byte-identical prior contract to preserve, so `.d.ts` fidelity is judged against the JS behavior + JSDoc, not a prior file.
- **1 impure async fn** — `getDescriptionLimit` does inline `require('./constants')` + `require('firebase-admin')` + a Firestore read. Kept as INLINE `require()` (typed `NodeRequire`→`any` via @types/node) — **NOT** converted to ES `import` (that would reintroduce logger's TS2307). This is why validators compiles FULLY locally (0 non-logger errors) despite the firebase-admin dependency.
- All other A′ infra is REUSED unchanged: scoped `functions/shared/tsconfig.json` (+1 include line), the `functions/shared/ts/**` ESLint block, `.gitattributes` LF pins, the CI build-drift guard (globs `functions/shared/*.{js,d.ts}` → auto-covers validators), and `newLine:"lf"`.
