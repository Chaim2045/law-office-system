# Rubric — PR-R4: inline flatpickr date-RANGE picker for the report tab (VENDORED)

**Track:** Report-tab reading-pane polish — the final piece. After PR-R3 (reading pane) shipped, the "מותאם" disclosure held two native `<input type="date">`. R4 replaces them with a single **inline flatpickr range calendar** (click start→end, range highlighted) — the product-owner-approved look — while the two hidden fields remain the source of truth.
**Scope:** frontend-only + ONE new **vendored** dependency (flatpickr 4.6.13, self-hosted). 5 change targets: 3 vendored files under `apps/admin-panel/vendor/flatpickr/`; `clients.html` (asset tags + `?v=` bumps); `ReportTab.js` (`_initRangePicker` + anchor + hooks + fallback); `clients-modals.css` (scoped theme overrides + disclosure height + hide-native); `report-tab.test.ts` (new tests). `getFormData` / the report engine / the manage tab / the CSP / netlify.toml — **UNTOUCHED**.
**Type:** admin-critical UI + a NEW third-party dependency → **devils-advocate MANDATORY** (§3.8.4 resource decision + supply-chain).

## MUST (all required for PASS)

- **M1 — `getFormData()` byte-identical.** The method body is unchanged (`git diff origin/main` shows zero hunk). flatpickr is only the input surface: its `onChange` writes `selectedDates[0/1]` into `#mgmtReportStartDate`/`#mgmtReportEndDate` via the EXISTING `fmtDateForInput` helper (byte-identical to the preset write path). `_computeUnassignedHours`/`parseLocalDate` untouched.
- **M2 — vendored + CSP-clean + provenance.** flatpickr **4.6.13** is self-hosted at `apps/admin-panel/vendor/flatpickr/` (`flatpickr.min.js` 50679 b, `flatpickr.min.css` 16166 b, `l10n/he.js` 925 b) — NO CDN, NO SRI needed (same-origin). SHA-256 of all three recorded in the PR body. Loaded as `'self'` → **zero CSP change** (the app's `netlify.toml`+meta CSP block jsdelivr CSS; self is permitted). The CSS `<link>` loads before `clients-modals.css`; the JS `<script defer>` pair loads before `ReportTab.js`.
- **M3 — inline mode (no popup).** `flatpickr(anchor,{mode:'range', inline:true, locale:'he', dateFormat:'Y-m-d'})` renders the calendar INLINE inside the disclosure — no `appendTo:body` popup → no z-index/clipping-outside-the-modal risk. The anchor is a hidden `type="text"` input (`#mgmtReportRangeAnchor`); flatpickr never binds a native `type="date"`.
- **M4 — loop-break + graceful fallback.** A preset click seeds the calendar via `fp.setDate([startDate,endDate], false)` (false = no onChange retrigger); `onChange` syncs only when `selectedDates.length===2`. If `window.flatpickr` is absent (load failure / jsdom), `_initRangePicker` returns immediately, the two native date inputs stay visible + usable, and `getFormData` works unchanged — **the tab never breaks**. The `this._fp` guard makes the preset `setDate` a no-op in fallback. `render()` destroys any prior instance before re-init (no leak across opens).
- **M5 — Design Bar (tokens + scope + reduced-motion).** Every flatpickr override uses EXISTING design-system tokens (no hardcoded hex beyond the R3 locals `--report-surface`/`--report-on-fg`); ALL `.flatpickr-*` overrides scoped under `.report-detail` (no global leak); `:focus-visible` via `--blue`; a `@media (prefers-reduced-motion:reduce)` block zeroes flatpickr's own hardcoded transitions/animations (Design-Bar MUST).
- **M6 — disclosure not clipped.** `.report-custom-dates--open` max-height raised (200→480px) so the ~340px inline calendar is not cut by the container's `overflow:hidden`. Native fields hidden (not removed) when active via `.report-custom-dates--fp .report-field{display:none}`.
- **M7 — gates.** Full admin-panel vitest green (479, was 473); ESLint 0 errors (pre-existing `no-alert` warnings untouched); stylelint 0; `node --check ReportTab.js` clean; `?v=` bumped on `ReportTab.js` + `clients-modals.css`; vendored assets carry `?v=fp-4.6.13`.
