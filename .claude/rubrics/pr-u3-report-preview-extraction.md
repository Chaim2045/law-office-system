# Rubric — PR-U3: extract `ReportPreview` from `ClientReportModal`

**Track:** Admin modal-unification (`docs/WORK-PLAN-MODAL-UNIFICATION.md`, PR-U3; spec §PR-U3).
**Scope:** frontend-only. NEW `apps/admin-panel/js/ui/ReportPreview.js` (the moved cluster) + `ClientReportModal.js` (cluster → delegates/removed) + `clients.html`/`clients-fluent.html` (script tag + `?v=`) + tests. Zero `functions/**`/rules/claims/callable.
**Type:** live-code MOVE (~600 lines) + 3 declared changes (Haim-approved "full package", 2026-08-02). BEHAVIORAL CHANGE declared (fix#2).

## The move

The timesheet preview + record-edit cluster (`showTimesheetPreview`, `renderTimesheetPreviewModal`, `closePreview`, `editEntryFromPreview`, `proceedToGenerateReport`, the toast/spinner helpers, `openEditTimesheetModal`→`openEditModal`, `saveTimesheetEdit`, `formatDate`) moved 1:1 into `ReportPreview`. State that was cluster-private (`previewData`) moved with it; shared bits (`getFormData`/`validateForm`/`showLoading`/`hideLoading`/`currentClient`/`dataManager`/`eventListeners`) stay on the host and are reached via `window.ClientReportModal`.

## MUST (all required for PASS)

- **M1 — payload byte-identical.** `saveTimesheetEdit`'s `updateTimesheetEntry` call carries the identical 9-field payload + `editHistory`/`autoGenerated` construction. The U0 source-guard now reads `ReportPreview.js` and passes. The host no longer contains the write (moved, not duplicated).
- **M2 — delegates keep external callers working.** `ClientReportModal` keeps thin delegates → `window.ReportPreview.*` for the 4 entry points: `showTimesheetPreview` (the `#generateReportBtn` handler at :110), `openEditTimesheetModal` (`ReportGenerator.editTimesheetEntry` caller), `closePreview`, `proceedToGenerateReport`. The in-preview onclicks point at `window.ReportPreview.*`.
- **M3 — DA-4 z-index.** Overlays bumped 10001/10002/10003 → 10600/10610/10620 (above the unified modal 10200 + status dialog 10500). Old values gone.
- **M4 — SEC-1 escape-at-sink.** The two previously-unescaped innerHTML sinks — the preview header `clientName` and the toast `message` (which carries a server `error.message`) — are routed through `window.escapeHtml`. The result is MORE secure than pre-move.
- **M5 — fix#2 (declared behavioral change).** Showing the preview no longer calls `host.close()`; `closePreview` only removes its overlay (no reopen) — retiring the pre-move `:1322` reopen-with-`currentClient=null` bug. Declared per admin-panel CLAUDE.md BEHAVIORAL CHANGE RULE.
- **M6 — eventListeners cleanup preserved.** `openEditModal` still pushes its close/cancel/save handlers to the HOST's `eventListeners` array, so `host.close()` tears them down (coupling intact).
- **M7 — no regression on the host's OTHER flows.** `generateReport`/`generateAndEmailReport` (NOT moved), `getFormData`/`validateForm`/`showLoading`/`hideLoading` (shared, kept), and `populateServiceCards`/`createServiceCard` are untouched and still work (the report-characterization suite stays green).
- **M8 — SSOT guard accurate.** ClientReportModal removed from the escapeHtml routed-escaper list (its wrapper moved out; ReportPreview calls the SSOT directly); ReportPreview added to the load-order set. escape-html.js loads before ReportPreview.js in both pages.
- **M9 — cache-bust + wiring.** `ReportPreview.js` script tag added to BOTH `clients.html` + `clients-fluent.html`, after `ClientReportModal.js` (which is after escape-html.js); `ClientReportModal.js` `?v=` bumped in both.
- **M10 — gates.** ESLint 0 errors (moved 1:1 console/alert warnings are inherited, not new-authored logic); `node --check` clean; full admin-panel suite green.
