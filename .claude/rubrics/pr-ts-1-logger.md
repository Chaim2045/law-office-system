## Mechanism (A′, subfolder-source variant — a correction discovered during build)
The naive "logger.ts at `shared/`" hit a real compiler conflict the investigation missed: once a `.ts` exists at the import path, the src-ts project (which imports `../shared/logger`) resolves to the SOURCE `.ts` over the `.d.ts` and errors **TS6059** ("not under rootDir src-ts"). Fix (verified): **source at `functions/shared/ts/logger.ts`; a scoped `functions/shared/tsconfig.json` (rootDir `./ts`, outDir `./`) emits `shared/logger.js` + `shared/logger.d.ts` at the exact legacy paths.** No `.ts` sits at `shared/logger` → src-ts resolves the import to the generated `.d.ts` (declaration files are exempt from rootDir) → TS6059 gone (verified). Still A′ in spirit: generated-in-place output, `.d.ts` drift killed.

## MUST
- **M1 — output is byte-PATH-identical.** The compile emits `functions/shared/logger.js` + `functions/shared/logger.d.ts` at the SAME paths they lived at before. **ZERO** `require`/`import` path changed anywhere in the repo. The 19 source consumers (18 TS `import * as logger from '../shared/logger'` + 1 legacy `functions/reconciliation/index.js` `require('../shared/logger')`) resolve unchanged.
- **M2 — surface preserved (named exports).** Emitted `logger.js` exposes `__esModule` + `exports.info/warn/error/debug/_raw` (verified: all 5 present). NOT `export =` (would break `import * as logger`). Legacy `logger.info(...)` AND TS `import * as logger` both keep working. The generated `.d.ts` declares the identical surface (`info/warn/error/debug: (action:string, fields?:LogFields)=>void` + `_raw`).
- **M3 — the TS6059 src-ts conflict is AVOIDED (the crux).** Source lives in `shared/ts/`, not `shared/`. Verified: `tsc --project src-ts/tsconfig.json --noEmit` no longer emits TS6059 / any error mentioning `shared/logger`. (The residual `firebase-functions/*` TS2307 errors are a LOCAL-node_modules artifact — pre-existing files share them; CI has the real deps.)
- **M4 — deterministic generated output.** `_raw` is explicitly annotated `unknown` in the source (NOT the inferred namespace type) so the generated `.d.ts` is env-independent → `export declare const _raw: unknown;` regardless of whether firebase-functions types resolve. The four fn signatures are explicitly typed. A fresh `build:ts` in CI must produce byte-identical committed output.
- **M5 — behavior is a 1:1 port.** Each method forwards `(action, fields)` to `firebase-functions/logger` exactly as before; `fields` defaults to `{}`; `_raw` is the same underlying module object. No PII-handling / severity / routing change — this is the logging primitive; its runtime behavior is IDENTICAL.
- **M6 — the missing anchor test added.** NEW `functions/src-ts/__tests__/logger.test.ts` (un-mocked, exercises the real compiled `shared/logger.js`): asserts the 4 methods are functions, `_raw` defined, forwarding `(action,fields)` via a spy on `_raw.*`, and the `{}` default. This is the pin that was ABSENT before (consumers all mock logger away).
- **M7 — build chain + LF pinned.** `functions/package.json` `build:ts` + `typecheck:ts` chain `shared/tsconfig.json` BEFORE `src-ts/tsconfig.json`. `.gitattributes` pins `functions/shared/logger.{js,d.ts}` + `ts/logger.ts` + `tsconfig.json` to `eol=lf` (tsc emits LF; without the pin a Windows checkout flips the committed output).
- **M8 — exec-log maintained (opens גל-3ה).** `docs/HEALTH-MAP` exec-log gains the TS-1 row (opens גל-3ה) + flips PR-DOCS-3 #495 to ✅ merged. Additive.
